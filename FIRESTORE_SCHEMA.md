# BOQ Pro — Firestore Database Schema

## Overview

This project uses **Firestore (Native Mode)** as its cloud database. The database must be created in the Firebase Console before the app can persist data to the cloud. The app uses IndexedDB (via Dexie) as a local-first cache and syncs to Firestore in the background.

---

## Collections & Documents

### 1. `profiles` — User Profiles

**Document ID:** `{user.uid}` (Firebase Auth UID)

```json
{
  "email": "user@example.com",
  "full_name": "John Doe",
  "company_name": "Doe Engineering Ltd",
  "company_key": "doe-engineering-ltd",
  "phone_number": "+2348012345678",
  "role": "Quantity Surveyor",
  "plan": "Student",
  "is_onboarded": true,
  "pending_subscription_selection": null,
  "subscription_status": "active",
  "subscription_id": "sub_xxxxxxxx",
  "subscription_expires_at": null,
  "paystack_customer_code": "CUS_xxxxxxxx",
  "paystack_authorization": null,
  "created_at": <Timestamp>,
  "updated_at": <Timestamp>
}
```

**Fields:**
| Field | Type | Description |
|-------|------|-------------|
| `email` | string | User's email address |
| `full_name` | string | Display name |
| `company_name` | string | Derived from email or user input |
| `company_key` | string | URL-safe key for company access queries |
| `phone_number` | string | Optional phone number |
| `role` | string | User role (e.g., "Quantity Surveyor", "Engineer") |
| `plan` | string | Plan name: "Student", "Starter", "Professional", "Business", "Corporate" |
| `is_onboarded` | boolean | Whether user completed onboarding |
| `pending_subscription_selection` | object/null | Pending plan selection before payment |
| `subscription_status` | string | "active", "inactive", "cancelled", "past_due" |
| `subscription_id` | string/null | Paystack subscription ID |
| `subscription_expires_at` | Timestamp/null | When subscription expires |
| `paystack_customer_code` | string/null | Paystack customer reference |
| `paystack_authorization` | object/null | Paystack authorization details |
| `created_at` | Timestamp | Profile creation time |
| `updated_at` | Timestamp | Last update time |

**Queries:**
- `getDoc(doc(db, 'profiles', userId))` — Get single profile by UID

**Queries:**
- `query(collection(db, 'projects'), where('user_id', '==', uid), orderBy('created_at', 'desc'))` — Get user's projects
- `query(collection(db, 'projects'), where('company_key', '==', key))` — Get company projects
- `query(collection(db, 'projects'), where('collaborator_ids', 'array-contains', email))` — Get shared projects
- `getDoc(doc(db, 'projects', id))` — Get single project by ID
- `query(collection(db, 'projects'), where('local_origin_id', '==', originId))` — Find project by local origin

## Required Composite Indexes

Firestore requires composite indexes for queries that use `where` + `orderBy` on different fields. Create these in the Firebase Console:

1. **Collection: `projects`**
   - Fields: `user_id` (ASC), `created_at` (DESC)
   - Used by: `getProjects()` — fetching user's own projects sorted by creation date

## Security Rules (Recommended)

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Profiles: only the owner can read/write their own profile
    match /profiles/{userId} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }

    // Projects: owner can read/write; collaborators can read; company members can read
    match /projects/{projectId} {
      allow read: if request.auth != null && (
        resource.data.user_id == request.auth.uid ||
        resource.data.collaborator_ids.hasAny([request.auth.token.email.lower()]) ||
        resource.data.company_key == request.auth.token.company_key
      );
      allow create: if request.auth != null;
      allow update, delete: if request.auth != null && resource.data.user_id == request.auth.uid;
    }

    // Settings: only the owner can read/write
    match /settings/{settingId} {
      allow read, write: if request.auth != null && settingId.startsWith(request.auth.uid);
    }

    // Materials: any authenticated user can read; only admins can write
    match /materials/{materialId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.token.admin == true;
    }

    // Market indices: any authenticated user can read; only admins can write
    match /market_indices/{indexId} {
      allow read: if request.auth != null;
      allow write: if request.auth != null && request.auth.token.admin == true;
    }
  }
}
```

## Steps to Create the Database

1. Go to https://console.firebase.google.com/project/boq-pro-72332/firestore
2. Click **"Create database"**
3. Choose **"Start in test mode"** (for development) or **"Start in production mode"** (with the rules above)
4. Select a Cloud Firestore location (e.g., `eur3` — Europe-west)
5. Click **"Done"**
6. After creation, go to the **"Indexes"** tab and add the composite index for `projects`:
   - Collection: `projects`
   - Fields: `user_id` (Ascending), `created_at` (Descending)
7. Optionally run the seed script to populate materials and market indices
